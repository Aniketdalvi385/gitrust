## B1 — Wrong actions and recovery traps 🔴

### F19 + F3 — the sync rule: ignores the named branch, runs backwards, catches pulls

**Symptom.** "merge develop into feature" / "pull develop into this branch" sync with *main*;
"merge feature into main" (on `feature`) brings main *into* feature; "Pull the latest from origin
into this branch" and "Update my branch from upstream" become *Update from main* instead of *Pull*.
All ⚡ exact-phrase routes — the model never gets a say.

**Root cause.** `capture_sync` ([`intent.rs:573-600`](../gitrust/src/intent.rs)) accepts
any request starting `pull/merge/bring … into` or `update/bring in … with/from`, without looking at
what is being brought in or where to. `FeaturePipelineOp::Sync { strategy }` has **no source
field**, and the Sync dispatch ([`agent.rs:1601-1608`](../gitrust/src/agent.rs)) always
reconciles against `default_branch(repo, remote)` ([`agent.rs:1864`](../gitrust/src/agent.rs)).

**Fix.**
1. Give Sync a source: `Sync { strategy, from: Option<String> }`; `reconcile_flow` uses `from` when
   set, else the default branch (today's behaviour for "sync with main").
2. `capture_sync` parses **source** and **destination**:
   - source is a remote word (`origin`, `upstream`, `remote`, `the latest`, `latest`, `changes`) →
     **not a sync**: return `None` so "pull …" falls to the exact `pull` rule or to Kev.
   - destination given and it is **not the current branch** ("into main" while on `feature`) →
     **not a sync** of the current branch: return `None` (Kev, then a menu if unsure). Never run it
     backwards.
   - source must be a ref-shaped token; if it names a branch that doesn't exist locally or on the
     remote → `None`.
3. The echo names the real source: "Update from develop".

**Lens.** Degenerate guards: source == current branch → "Nothing to bring in — that's this branch"
(exit 1, no gate). The reconcile gate must keep its existing ahead==0 / behind==0 guards for the new
source too.

**Tests first** (`intent.rs`, fresh phrasings — never the eval rows):
`merge develop into feature` (on feature) → Sync{from: develop}; `merge feature into main` (on
feature) → not Sync; `pull the newest from origin into my branch` → not Sync; `update my branch
from upstream` → not Sync; `sync with main` → Sync{from: None} (unchanged); `pull main into feature`
(on feature) → Sync{from: main} (M-10c unchanged).
**Suite:** new **M-43** (merge develop into feature → feature contains develop's commit, not
main's), **M-44** (pull the latest from origin into this branch → pull). **Eval:** the two v3
instant-WRONG rows become right.

### F7 — the paused pipeline's snapshot can undo a finished rebase

**Symptom.** After a conflict pause the next command shows "An interrupted pipeline was found —
Run 'gitrust --recover'…". GiTrust's own `continue rebase` clears the snapshot afterwards
([`agent.rs:2733-2756`](../gitrust/src/agent.rs), the v0.3.0 fix), but **finishing with
plain `git rebase --continue` leaves it**, and then:

**Root cause.** The pause deliberately keeps the snapshot ([`agent.rs:2716-2722`](../gitrust/src/agent.rs)).
The snapshot was captured on `main` (attached) before the rebase, so on a now-clean repo
`recovery_plan` ([`recovery.rs:48-72`](../gitrust/src/recovery.rs)) returns **`Restore`** —
resetting the branch to before the rebase, discarding the user's resolution (reachable only via the
reflog). The banner ([`agent.rs:128-135`](../gitrust/src/agent.rs)) advertises exactly that.

**Fix.**
1. At the pause, mark the snapshot **handed off**: `PipelineSnapshot.handed_off: Option<String>`
   (`"rebase"`/`"merge"`, `#[serde(default)]` so old files still load), written before returning the
   calm handoff.
2. `check_for_interrupted` never banners a handed-off snapshot. While git is still mid-operation,
   status already explains what to do.
3. A handed-off snapshot on a **clean** repo means the operation was finished (by GiTrust or plain
   git): delete it silently — git's ORIG_HEAD and reflog own that history now.
4. `recovery_plan`: handed-off + clean → new `RecoveryDecision::FinishedElsewhere` ("That rebase was
   finished — there's nothing to restore. Earlier states are in `git reflog`."), **never `Restore`**;
   exit 1 per D4.

**Lens — re-entrancy.** Only snapshots *explicitly marked at a pause* are auto-cleared; a genuinely
crashed pipeline (no mark) keeps its banner and `--recover`. Test both.
**Tests first** (`recovery.rs`): `recovery_plan(Clean, handed_off snapshot, moved HEAD)` →
`FinishedElsewhere`; unmarked snapshot → `Restore` (unchanged); `check_for_interrupted` skips marked
snapshots. **Suite:** new **M-45** — push → conflict pause → resolve with plain `git rebase
--continue` → `gitrust status` shows no banner → `gitrust --recover` exits 1 and HEAD is unchanged.

### F6 — the detached-HEAD rescue acts before the plan is confirmed

**Symptom.** Choosing "Create a branch HERE" creates and checks out the branch and stages
everything; the original request's plan comes after. `q` at that plan leaves the branch and the
staging behind — and the cancel line says "nothing was done".

**Root cause.** `handle_detached_head_rescue` ([`agent.rs:3683-3694`](../gitrust/src/agent.rs))
calls `create_branch`, `checkout` and `add_all` directly, then returns `RescueOutcome::Resume`.

**Fix.** The rescue only *decides*: `RescueOutcome::ResumeOnNewBranch { name }`. The resumed
request's plan gets the existing `PipelineStep::Branch` + `PipelineStep::Checkout` as its first
steps (no separate add-all: the resumed commit plan already stages). One plan, one confirmation, `q`
cancels everything. The branch name is validated before the plan renders (today's sanitiser).
For the stranded-commit case (M-14), the plan is Branch → Checkout(target).
**Tests first:** a `SequenceGate` test — choose branch-here, cancel at the plan → no new branch,
HEAD still detached, index unchanged, error is `Canceled`. **Suite:** new **M-46** (q at the plan
after the rescue choice → nothing changed); M-13/M-14 keep passing.

### F4 — stash vs stash pop confused; empty stash fails raw

**Root cause.** Kev ranked `stash_pop` 0.91 for "Park my local modifications on the stash stack";
`intent::conflicting_op` ([`intent.rs:995-1012`](../gitrust/src/intent.rs)) has no rule for
the stash direction. There is no pre-check for popping an empty stash, so libgit2's error surfaces
(`reference 'refs/stash' not found`) — though `RepoContext.has_stash` already exists.

**Fix (D9).**
1. `conflicting_op`: `stash_pop` without a retrieval word (`pop`, `back`, `restore`, `apply`,
   `unstash`, `reapply`, `retrieve`, `bring`, `get … back`) → `Some("stash")` (menu of both);
   `stash` *with* one → `Some("stash_pop")`.
2. Pre-check for `StashPop`: no stash → Block "There are no stashed changes to bring back." (exit 1).
   Uses `context.has_stash` before any step runs.
3. Later (round-3 fine-tune, optional): fresh stash/pop contrast phrasings.
**Tests first:** `conflicting_op("stash_pop", "park my edits on the stash")` → `Some("stash")`;
`conflicting_op("stash_pop", "bring back what i stashed")` → `None`; StashPop pre-check blocks on an
empty stash. **Suite:** new **M-47** (stash pop with no stash → plain message, exit 1). **Eval:** the
v3 acted-WRONG (changes something) row becomes a menu.

### F20 — a recovery option drafts a commit message

**Root cause.** The dirty-tree recovery picker's "Commit → pull" option builds
`PipelineStep::Commit { message: "update" }` ([`agent.rs:2163-2176`](../gitrust/src/agent.rs)).
**Fix (D8).** Before running that recovery pipeline, ask for the message through
`resolve_or_generate_commit_message` (empty → canceled, `--yes` → refused) — the same path every
other commit uses. **Test first:** a `SequenceGate` test asserting the recovery commit uses the
provided message and that no code path constructs `Commit { message: "update" }`.

## B2 — The crash, exit codes, honest messages 🔴

### F1 — panic when stdout closes (`gitrust … | head`)

**Root cause.** Rust ignores SIGPIPE, so a write to a closed pipe returns `EPIPE`, and `println!`
panics on it ("failed printing to stdout", exit 101). There are **288** `print!`/`println!` sites.
**Fix (D5).** In `main.rs`, before the `mod` declarations, shadow `println!`/`print!` (and
`eprintln!`/`eprint!`) with macros that write via `std::io::Write` and **ignore** errors; under
`cfg(test)` they forward to the std macros so test output capture keeps working. No call site
changes. The operation always runs to completion; the exit code reports its outcome.
**Test first:** the crate's first integration test (`gitrust/tests/closed_pipe.rs`): run the built
binary (`CARGO_BIN_EXE_gitrust`) on `--yes "show history"` in a temp repo with stdout closed
immediately → exit ≠ 101, stderr has no "panicked". **Suite:** M-41 passes.

### F16 — "nothing to do" exits (D4)

**Root cause.** `--recover` with no snapshot ([`agent.rs:2880`](../gitrust/src/agent.rs))
and "find my lost work" with nothing found ([`agent.rs:3372`](../gitrust/src/agent.rs))
both `return Ok(())`.
**Fix.** Apply the D4 rule: `--recover` with nothing → `Err` (exit 1) with the same calm text;
find-nothing stays 0 (a query that ran). Write the rule into `gitrust/CLAUDE.md` (Interaction
conventions) so future paths follow it. **Tests first** for both; **suite** M-25 (0) and M-28
(changes to 1 — update its expectation).

### F8 — after a failed step: dead-end menus and "nothing was done" when something was

**Root cause.** `handle_classified_recovery` ([`agent.rs:2110-2290`](../gitrust/src/agent.rs))
renders a "Pick one:" menu for every failure class; several options do nothing (`Show` prints "the
output was printed above", `Wait` prints "retry when ready", `Verify` runs `ls-remote`), every menu
has a **Cancel** row, and `Unknown` gets a menu with *only* Cancel. Backing out prints the generic
"Canceled — nothing was done." although earlier steps ran (M-21: the files stay staged). The step
error is also printed twice (under the step, then by `main`).
**Fix (D7).**
1. Menus only where an option runs a real pipeline (dirty tree blocks pull: Stash → pull → restore;
   network: Retry). Everything else → a plain message with the next step, e.g. hook rejected: "The
   pre-commit hook refused the commit (output above). Your files are still staged — fix what it
   reported, then run gitrust "commit" again." Lock held: "Another git process is running — try
   again when it finishes." Auth: the `ls-remote` check runs automatically and its result is printed.
2. No Cancel rows (Esc cancels, as everywhere).
3. **Honest cancel after partial work:** `ux::canceled_after(done: &[completed step labels])` →
   "↪ Stopped — staged 2 files; nothing was committed." Exit 1. Used wherever a cancel can follow
   executed steps.
4. Print a failed step's error once.
5. Drop the "Snapshot preserved / Run --recover" lines when the only completed steps are
   index-only (stage/unstage) — nothing to restore that matters.
**Tests first:** hook-rejected recovery → no prompt is shown (SequenceGate expects none) and the
message names the staged files; cancel after a completed Add step → message lists what was done.
**Suite:** M-21 updated: no "Pick one", screen shows "still staged", exit 1.

## B3 — One confirmation, after the plan; consistent menus 🟠

### F9 — double confirmation (D1)

**Root cause.** Six type-to-confirm gates run *before* the plan: force push
([`agent.rs:1396`](../gitrust/src/agent.rs)), reset to the remote (`1429`), reset --hard
(`1563`), delete the repository (`3007`), undo-and-discard (`3211`), rewriting pushed history
(`3577`); revert asks its own `(Y/n)` (`3465`). The plan prompt follows each.
**Fix.** Extend `GateType::RunPlan` with `typed: Option<TypedConfirm { expected, message,
explanation }>`. When set, the plan renders, the explanation block follows, and the prompt is the
typed value instead of Enter (Esc/q cancel). Remove the six pre-plan gates and the revert `(Y/n)`;
their `expected`/`message`/`explanation` move onto the plan. **Load-bearing:** `AutoConfirmGate`
must refuse a `RunPlan` with `typed` set exactly as it refuses `TypeToConfirm` today (`--yes` never
clears a typed confirmation) — test it.
**Tests first:** for each of the six flows, a `SequenceGate` run sees exactly one confirmation
prompt and it is the typed one; `--yes` on each is refused (exit 1). **Suite:** M-16, M-20, M-22
updated to one confirmation.

### F11 — clean-up has no typed confirmation (D2)

**Root cause.** The clean-up gate maps choices to `Reset{Hard}` / `Clean` steps
([`agent.rs:3297-3315`](../gitrust/src/agent.rs)) and goes straight to the plan with Enter,
while the same `Reset{Hard}` asked directly requires typing (`agent.rs:1563`).
**Fix.** With D1 in place: clean-up plans carry `typed` (expected `"discard"` / `"delete"` /
`"both"` — short words, not a SHA). **Tests first:** clean-up plan requires the typed word; `--yes`
refuses. **Suite:** M-26/M-27 expect the typed step.

### F10 — old-style menus

**Root cause.** Four `GateType::Choose` menus — un-numbered, with "Cancel" rows: the detached-HEAD
rescue ([`agent.rs:3644`](../gitrust/src/agent.rs)), the recovery picker (`2251`, see F8),
and two more (`1122`, `2054`; `1119`/`2051` push the Cancel label).
**Fix.** Move all four to `GateType::ChoiceGate` (numbered via `ux::pick_one`, consequence per
option), drop every Cancel row, fix the rescue copy: "Create a branch here to keep this work" /
"Switch to main and leave this commit" (it never switched to the *previous* branch). Then delete
`GateType::Choose` if nothing else produces it (lens: no variant without a producer).
**Test first:** a source-level test asserting no option list contains a "Cancel" label (catches
regressions anywhere). **Suite:** M-13/M-14 see a numbered menu without Cancel.

## B4 — Errors in plain words 🟠

**Policy (cross-cutting).** `main` prints the error chain unconditionally
([`main.rs:123-128`](../gitrust/src/main.rs)). Change: print the top-level message; print
`caused by:` lines only under `GITRUST_DEBUG=1`, and otherwise add one dim line "(details:
GITRUST_DEBUG=1)" when a chain exists. Every *known* failure gets a self-sufficient top-level
message — the three below.

### F2 — trash backup can't be written
**Root cause.** `trash.rs:51` `with_context("Failed to create trash dir <full path>")` over the io
error; printed under the step and again by `main`. **Fix.** A typed `TrashUnavailable { dir }` error
whose message is: "Couldn't back up your files first, so nothing was deleted. Check that
~/.gitrust/trash is writable." (tilde path). Printed once. **Test first:** unwritable trash →
message as above, no "caused by", file intact. **Suite:** M-27 passes.

### F18 — switching branches with an edit in the way
**Root cause.** `Git2Operations::checkout` ([`git_ops.rs:1003`](../gitrust/src/git_ops.rs))
surfaces libgit2's `1 conflict prevents checkout; class=Checkout (20)`. **Fix.** A Checkout
pre-check: a libgit2 dry-run checkout (`CheckoutBuilder::dry_run` + conflict notifications)
collects the files that would be overwritten → Block: "Switching to other would overwrite your
uncommitted changes to app.txt. Commit them (gitrust "commit everything") or stash them (gitrust
"stash") first." (SafeSwitch auto-stash stays on the backlog.) **Test first:** dirty conflicting
switch → Block with the file named; non-conflicting dirty switch still allowed. **Suite:** M-05
passes.

### F15 — the `--yes` refusal when the model is down
**Root cause.** `AutoConfirmGate`'s ChoiceGate refusal ([`confirm.rs:417-432`](../gitrust/src/confirm.rs))
pastes the menu question into a sentence and lists every option (35 here). **Fix.** Cap the list at
6 ("… and 29 more"); for the model-down menu use its own message: "The local model isn't running,
so GiTrust can't tell which operation you mean — and --yes won't choose for you. Start it with
`gitrust setup`, or use an exact phrase (`gitrust help`)." **Test first** on the refusal text.
**Suite:** M-29 run 2 lacks "type to filter".

## B5 — Argument capture 🟠 (F5)

**Root cause** ([`intent.rs:1017-1110`](../gitrust/src/intent.rs)): requests are split on
spaces only, so `branch,` never equals `branch`; topic capture knows a fixed list of verb openings
("push only …", "ship …"); checkout looks only after "to/onto"; a quoted message ("with message
'login page'") is parsed as part of the topic phrase.

**Fix.**
1. Tokenise with punctuation stripped (commas, periods, quotes) — one helper used by all captures.
2. Remove quoted spans before topic/branch capture (they are the commit message).
3. New branch: the ref-shaped token right after "branch" ("a fresh branch, release/2.4"), when it
   is ref-shaped (has `/`, `-`, `.`, or a digit — so "branch for" never captures "for").
4. Checkout: **any token that names an existing branch** (local or remote-tracking) — needs
   `RepoContext.branches: Vec<String>` (new, cheap). Deterministic and safe: only real branches.
5. Topic: the grammar `(only|just) [the] <topic> [related] (files|changes|work|part|module|code|stuff|bits)`
   and `my <topic> work`; then a fallback that picks a request word appearing in a changed file's
   path. No match → the user is asked, as today.

**Guard against overfitting.** The eval's v3 rows are the yardstick, never the unit tests: write
fresh test phrasings for each rule, then measure on v3. **Tests first** in `intent.rs` per rule.
**Suite:** M-04 with "push the login changes with message 'login page'" (now captured).
**Eval target:** v3 "acted+arg-asked" 9 → ≤ 3, no new wrong rows.

## B6 — Output polish 🟡

- **F12 raw git output (D6).** `run_git_in_repo` / `run_git_noninteractive`
  ([`git_ops.rs:328`, `:347`](../gitrust/src/git_ops.rs)) inherit the terminal. Capture
  stdout/stderr and show them indented under the step only on failure (hook output included).
  Credential and passphrase prompts are unaffected — git and ssh prompt on `/dev/tty`, not the
  captured streams; verify with a push to an https remote needing a credential before merging.
  **Suite:** M-06/M-08/M-10/M-20/M-22/M-26 gain `lacks("Successfully rebased")`,
  `lacks("Enumerating objects")`, `lacks("Removing ")`.
- **F13 "Consider pulling first."** [`validation.rs:382-391`](../gitrust/src/validation.rs)
  warns whenever the plan pushes and the branch is behind. Skip it when a Rebase/Merge/Pull/PullRebase
  step precedes the Push. Test: reconcile+push plan → no warning. Suite: M-06/M-07 lack it.
- **F14 squash message (D3).** [`agent.rs:3534-3546`](../gitrust/src/agent.rs) seeds the
  prompt with `summaries.join("\n")`. Per D3: empty prompt, the subjects listed above it; the plan
  shows one line ("… (+N lines)") for any multi-line message.
- **F17 copy.**
  - Multi-commit undo is caught at execution ([`agent.rs:3089`](../gitrust/src/agent.rs))
    after the echo said "Undo the last commit" — move the count check into `build_from_op("undo")`
    so the guidance comes first.
  - The lost-work browser lists the internal "index on main" stash commit
    ([`recovery.rs:559`](../gitrust/src/recovery.rs)) — skip "index on …" / "untracked files
    on …" commits that are parents of a listed stash.
  - The conflict pause doesn't name the files — `reconcile_paused_block(op, n)`
    ([`copy.rs:207`](../gitrust/src/copy.rs)) takes the paths (up to 3).
  - Checkout of the current branch: "Already on main." (exit 0 — the end state holds; D4).
  - Menu hints cut with "…": shorten the rebase/merge consequences
    ([`copy.rs:191-203`](../gitrust/src/copy.rs)) to fit 80 columns.
  - No-terminal advice ([`copy.rs:499`](../gitrust/src/copy.rs)) suggests `--yes` even for
    choices `--yes` refuses — two messages: a choice ("Run it in a terminal to choose") vs a
    confirmation (the `--yes` hint).
  - Undo-discard "Risks" ([`explain.rs:90`](../gitrust/src/explain.rs)) says uncommitted
    work "is gone" — say it is backed up to ~/.gitrust/trash for 7 days.
  - From the reviews: the post-sync note "re-run and confirm" (M-10) → "Push it with gitrust "force
    push" (uses --force-with-lease)"; revert's prompt names the commit's subject, not just its SHA
    (M-22); "discarded changes" → "deleted files" for untracked backups (M-26).
